# 舵机速度降低优化

## 🎯 问题背景

用户反馈：每次出现顺时针/逆时针动作后出现重启问题。通过日志分析发现重启原因是 `reset reason: 0`（上电重启），可能是舵机动作时电流消耗过大或动作过于激烈导致的。

## 🔧 优化方案

### 1. 降低舵机移动速度

**修改前**：
```c
#define SERVO_FAST_MOVE_TIME_MS      200     // 快速移动时间
#define SERVO_SLOW_MOVE_TIME_MS      600     // 慢速移动时间
```

**修改后**：
```c
#define SERVO_FAST_MOVE_TIME_MS      400     // 快速移动时间（降低一倍）
#define SERVO_SLOW_MOVE_TIME_MS      1200    // 慢速移动时间（降低一倍）
```

### 2. 增加动作间隔延时

**顺时针动作延时优化**：

| 动作步骤 | 修改前延时 | 修改后延时 | 变化 |
|---------|-----------|-----------|------|
| 初始延时 | 100ms | 200ms | +100ms |
| 主要动作间隔 | 150ms | 300ms | +150ms |
| 第二循环间隔 | 100ms | 200ms | +100ms |

**逆时针动作延时优化**：

| 动作步骤 | 修改前延时 | 修改后延时 | 变化 |
|---------|-----------|-----------|------|
| 初始延时 | 100ms | 200ms | +100ms |
| 主要动作间隔 | 150ms | 300ms | +150ms |
| 第二循环间隔 | 100ms | 200ms | +100ms |

## 📊 时间对比分析

### 修改前总时间：
```
- 快速移动：200ms × 8次 = 1600ms
- 慢速移动：600ms × 2次 = 1200ms  
- 延时：100ms + 150ms×4 + 100ms×2 = 900ms
- 总计：≈ 3700ms (3.7秒)
```

### 修改后总时间：
```
- 快速移动：400ms × 8次 = 3200ms
- 慢速移动：1200ms × 2次 = 2400ms
- 延时：200ms + 300ms×4 + 200ms×2 = 1800ms
- 总计：≈ 7400ms (7.4秒)
```

## ✅ 优化效果

### 1. 降低电流冲击
- **移动速度减半**：减少舵机瞬间电流消耗
- **增加延时**：给电源系统更多恢复时间
- **平缓动作**：减少机械冲击

### 2. 提高系统稳定性
- **减少电源压力**：避免电压波动
- **降低硬件负载**：减少舵机过载风险
- **改善动作流畅性**：更平滑的运动轨迹

### 3. 保持功能完整性
- **动作序列不变**：保持顺时针/逆时针的完整动作
- **视觉效果保持**：动作依然流畅自然
- **功能不受影响**：所有手势响应正常

## 🔍 技术细节

### 速度控制原理：
```c
// 舵机移动速度由以下因素决定：
1. SERVO_FAST_MOVE_TIME_MS - 快速移动时间
2. SERVO_SLOW_MOVE_TIME_MS - 慢速移动时间  
3. tal_system_sleep() - 动作间隔延时
4. app_servo_move_to_with_speed() - 内部步进控制
```

### 动作序列：
```c
// 顺时针动作序列：
1. 回中 → 延时200ms
2. 右 → 延时300ms
3. 下 → 延时300ms  
4. 左 → 延时300ms
5. 上 → 延时300ms
6. 右(第二循环) → 延时200ms
7. 下(第二循环) → 延时200ms
8. 回中(慢速)
```
